# Acceptance Criteria

- Register and install the Trading Lab capability is implemented with production code, not placeholder behavior.
- Relevant state is persisted and can be read back when the capability owns data.
- The affected API, route, screen, workflow, or operator action is identified in the PR evidence.
- Focused automated tests cover success and meaningful failure behavior.
- Sprint criterion remains demonstrable: The System Trading workspace is visible in System Builder with repository metadata and Trading Lab installed.
