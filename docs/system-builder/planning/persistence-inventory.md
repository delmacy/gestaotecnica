# Persistence Inventory: Mock & Static Data Surfaces

This document catalogs launch-critical mock and static data surfaces identified within the Builder. It serves as an inventory for the CL-03 persistence lane, providing a clear list of surfaces that require persistence implementation for commercial launch.

## Discovery Methodology

This inventory was generated by strictly scanning the allowed context boundaries (`docs/system-builder/planning/**`, `docs/ui/reviews/**`) along with known builder features referenced within the reviews to identify what mock, synthetic, or static data boundaries exist today.

The following grep commands were used to reproduce the discovery:

```bash
# Search for mock references in UI reviews:
grep -rn -E -i "(mock|static.*data|data.*static)" docs/ui/reviews/

# Identify the underlying source files representing the data:
grep -rn -E -i "(mock|static.*data|data.*static)" src/components/builder/ | grep data
```

## Inventory

### 1. Form Builder

* **Surface:** `src/components/builder/form-builder/form-builder-data.ts`
* **Description:** Contains `MOCK_FORM_BUILDER_DATA`, representing mock forms, schemas, fields, and workflow integration boundaries. Currently operates in `synthetic` and `mock_ready` modes.
* **Consumption:** Rendered by `FormBuilderStudio` as design-only fixtures.
* **Launch-readiness Status:** Blocked (needs real schema/DB support).
* **Launch Criticality:** Yes (Launch Blocker). Core capability for defining UI shapes and data ingestion. Must be backed by database persistence.

### 2. Workflow Builder

* **Surface:** `src/components/builder/workflow-builder/workflow-builder-data.ts`
* **Description:** Defines `mockBlueprints`, establishing mock workflow definitions, steps, condition logic, and capability attachments.
* **Consumption:** Rendered by `WorkflowBuilderStudio` as visual steps.
* **Launch-readiness Status:** Blocked (needs process definition persistence).
* **Launch Criticality:** Yes (Launch Blocker). Core orchestrator function. Needs persistence in `process_definitions`.

### 3. Gap Tracker

* **Surface:** `src/components/builder/gap-tracker/gap-tracker-data.ts`
* **Description:** Contains `mockGaps`, representing findings from system audits and as-is mirroring.
* **Consumption:** Displayed by `GapTracker` to reflect internal dev gaps.
* **Launch-readiness Status:** Deferred (Acceptable to launch with mock internal tools initially, if not blocking tenant functionality).
* **Launch Criticality:** Moderate. While important for implementation, the tracker itself is an internal tool. However, the underlying gaps it identifies *are* launch-critical.

### 4. Process Mirroring (As-Is Mirror & Intake)

* **Surfaces:**
  * `src/components/builder/as-is-mirror/as-is-mirror-data.ts`
  * `src/components/builder/process-mirroring/process-mirroring-data.ts`
* **Description:** Contains mock definitions for process pilots (`mockPilots`) and legacy system workflows/steps.
* **Consumption:** Read by `ProcessMirroringIntake` for legacy discovery.
* **Launch-readiness Status:** Blocked (Needs pilot onboarding workflow persistence).
* **Launch Criticality:** Yes. Needed for onboarding and mapping legacy systems to the new architecture.

### 5. Capabilities Explorer

* **Surface:** `src/components/builder/capabilities/capability-data.ts`
* **Description:** Defines the core system capabilities and registry entries as synthetic mock data.
* **Consumption:** Used to seed `CapabilityExplorer` and define limits.
* **Launch-readiness Status:** Blocked (Modules/Capabilities need persistence).
* **Launch Criticality:** Yes (Launch Blocker). The capability registry defines what modules are active and accessible.

### 6. Shell & Navigation State

* **Surface:** `src/components/builder/shell/shell-data.ts`
* **Description:** Contains `MOCK_USER`, `MOCK_WORKSPACES`, and navigation state hardcoded as "mock".
* **Consumption:** Used globally by `Topbar` and layouts to define tenant isolation.
* **Launch-readiness Status:** Blocked (Workspace and Auth must be real DB checks).
* **Launch Criticality:** Yes (Launch Blocker). Multitenancy, workspace isolation, and RBAC must be fully persistent and driven by the database.

### 7. View Builder

* **Surface:** `src/components/builder/view-builder/view-builder-data.ts`
* **Description:** Provides static models and fixtures for view rendering.
* **Consumption:** Read by `ViewCanvas` as read-only fixtures.
* **Launch-readiness Status:** Blocked (Requires dynamic UI building persistence).
* **Launch Criticality:** Yes. Needs to read from compiled artifacts or persistent definitions rather than static files.

### 8. Enterprise Map

* **Surface:** `src/components/builder/enterprise-map/enterprise-map-data.ts`
* **Description:** Mock definition of organizational taxonomy, departments, and nodes.
* **Consumption:** Rendered by `EnterpriseMapStudio`.
* **Launch-readiness Status:** Acceptable (Tenants could be manually configured initially).
* **Launch Criticality:** Moderate/High. Important for tenant configuration, but might be manually configured initially.

### 9. Tasker

* **Surface:** `src/components/builder/tasker/tasker-data.ts`
* **Description:** Mock task assignments, status, and metadata.
* **Consumption:** Used by `TaskerBoard` to show execution state.
* **Launch-readiness Status:** Blocked (Tasks must be tied to engine/DB).
* **Launch Criticality:** Yes (Launch Blocker). Runtime execution of workflow steps requires real, persistent tasks tied to the engine.

### 10. Governance Matrix

* **Surface:** `src/components/builder/governance-matrix/governance-matrix-data.ts`
* **Description:** Defines mock permission models, roles, and capability authorizations.
* **Consumption:** Consumed by `GovernanceMatrixStudio` to set up tenant limits.
* **Launch-readiness Status:** Blocked (Needs RBAC/Workspace database isolation).
* **Launch Criticality:** Yes (Launch Blocker). Tied to RBAC and workspace isolation gaps. Must be persistent.

### 11. Operator Guide

* **Surface:** `src/components/builder/operator-guide/operator-guide-data.ts`
* **Description:** Configured with `data_source_mode: "static_documentation"`.
* **Consumption:** Rendered as read-only docs by `OperatorGuideStudio`.
* **Launch-readiness Status:** Acceptable (Static markdown is fine for early launch).
* **Launch Criticality:** Moderate. Operational procedures could remain static markdown initially, but dynamic guides are preferred.

### 12. Registry

* **Surface:** `src/components/builder/registry/registry-data.ts`
* **Description:** Mock data for the system capability registry.
* **Consumption:** Read by `RegistryView` to list all services.
* **Launch-readiness Status:** Blocked.
* **Launch Criticality:** Yes.

### 13. Docs Viewer & UI Contracts

* **Surfaces:**
  * `src/components/builder/docs/docs-data.ts`
  * `src/components/builder/ui-contracts/ui-contracts-data.ts`
* **Description:** Static index for documentation and UI contract mockups.
* **Consumption:** Rendered as markdown viewer for dev references.
* **Launch-readiness Status:** Acceptable (Developer-only tools do not need complex DB persistence).
* **Launch Criticality:** Low. This is mainly developer/builder documentation and reference.

### 14. Source Intake

* **Surface:** `src/components/builder/source-intake/source-intake-data.ts`
* **Description:** Mock data for legacy source system file uploads.
* **Consumption:** Rendered by `SourceIntake` as an upload mock.
* **Launch-readiness Status:** Blocked.
* **Launch Criticality:** High. Needed for onboarding evidence processing.
