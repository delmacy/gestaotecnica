# Gap Tracker Visual Model

## 1. Objetivo visual
Fornecer uma interface clara e organizada para listar e detalhar gaps do processo em modo mock.

## 2. Layout recomendado
- Layout estilo master/detail: lista lateral ou tabela central, com painel de detalhes (side-panel ou bottom).

## 3. Áreas da tela
- Header da superfície com título e botão de ações globais simuladas.
- Barra lateral de filtros ou barra superior (tipo, status, etc).
- Área principal dividida entre lista e painel de detalhe.

## 4. Lista de gaps
- Tabela ou cards com colunas/labels para Status, Severidade, Tipo e Título.

## 5. Painel de detalhe do gap
- Painel para mostrar toda a riqueza de detalhes do gap focado.

## 6. Matriz de risco/impacto
- Exibição visual combinando Impacto e Risco (quadrante ou badges).

## 7. Fontes requeridas
- Aba ou seção listando documentos ou sistemas ausentes.

## 8. Evidências ausentes
- Aba ou seção listando fotos, logs, etc. não encontrados.

## 9. Observações relacionadas
- Links simulados ou IDs de observações no PM Intake.

## 10. Capability candidates relacionadas
- Capacidades sugeridas para sanar a etapa ou gap.

## 11. Next action
- Bloco destacando o que precisa ser feito (ex: Entrevistar técnico).

## 12. Owner/role
- Pessoa ou departamento responsável pela informação faltante.

## 13. Badges de origem de dados
- Exibição de modo: synthetic, mock, real_pending, real_blocked.

## 14. Badges de status
- Cores distintas para open, blocked, etc.

## 15. Badges de risco
- Cores (ex: Vermelho para Critical/Blocking).

## 16. Limites do MVP
- Header persistente: "Synthetic/Mock Mode".
- Bloco de aviso no detalhe: "No real gaps are resolved in this phase".
